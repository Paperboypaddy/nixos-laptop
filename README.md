# nixos-laptop

NixOS configuration for a Dell Latitude 5420 (Intel i5, NVMe), dual-booted
alongside Windows 11. The setup is built around Sway, a terminal-and-browser
workflow, and aggressive battery power management.

## Repository layout

| Path | Purpose |
|------|---------|
| `configuration.nix` | Main NixOS system configuration |
| `hardware-configuration.nix` | Hardware-specific configuration generated by NixOS |
| `sway/config` | Sway keybindings, output/input settings, and session startup |
| `sway/session.py` | Automatic session snapshots and window restoration |
| `sway/update.sh` | Interactive configuration updater |
| `sway/update-check.sh` | Background checker that notifies when commits are available |
| `sway/update-status.sh` | Waybar helper that reports whether updates are pending |
| `waybar/config.jsonc` | Waybar modules and layout |
| `waybar/style.css` | Waybar styling |
| `librewolf.overrides.cfg` | Tracked LibreWolf preference overrides |

The NixOS configuration installs these files at their system paths:

- `sway/config` → `/etc/sway/config`
- `waybar/config.jsonc` → `/etc/xdg/waybar/config.jsonc`
- `waybar/style.css` → `/etc/xdg/waybar/style.css`

The repository is cloned to `~/nixos-config`, and `/etc/nixos` points to
that clone. This lets NixOS evaluate the configuration and its relative file
references directly from the checkout.

## What's configured

- **Boot:** GRUB on EFI, reusing the existing Windows EFI partition at
  `/boot/efi`. NixOS lives on its own ext4 partition.
- **Desktop:** Sway, started through greetd/tuigreet. foot terminal, wmenu
  launcher, mako notifications, and Waybar. The internal display is scaled
  to 1.12.
- **Power:** TLP plus thermald. On battery: powersave governor, turbo disabled,
  and CPU frequency capped at about 700 MHz. On AC: boost is enabled and the
  power policy is more performance-oriented.
- **Browser:** LibreWolf. The tracked `librewolf.overrides.cfg` is linked into
  `~/.config/librewolf/librewolf/` and the legacy `~/.librewolf/` directory
  by systemd-tmpfiles rules. Previous browser windows and tabs are restored
  automatically.
- **Authentication:** Howdy face authentication using the IR camera, with
  password authentication retained as a fallback.
- **Shell:** fish.
- **Passwords:** Bitwarden desktop.
- **Networking:** NetworkManager, OpenSSH, common network troubleshooting
  tools, and WireGuard.
- **Ethernet/Wi-Fi behavior:** A NetworkManager dispatcher script disables
  Wi-Fi when Ethernet connects to the same gateway, then restores Wi-Fi when
  Ethernet disconnects.
- **WireGuard:** The `homelab` tunnel uses
  `/etc/wireguard/homelab.conf` and remains configured to autostart. The
  private WireGuard configuration stays outside this repository. Waybar shows
  a shield immediately to the left of the battery: green means connected,
  muted means disconnected. Hover for status; click to toggle the tunnel.
  The toggle uses a narrowly scoped passwordless sudo rule for the
  `wg-toggle` helper, which can only start or stop this one tunnel.

## Keybindings

Sway's modifier (`$mod`) is the Super/Windows key.

| Keys | Action |
|------|--------|
| `$mod+Enter` | Open foot terminal |
| `$mod+D` | Open application launcher |
| `$mod+Shift+B` | Open LibreWolf |
| `$mod+Shift+U` | Open the interactive configuration updater |
| `$mod+Shift+C` | Reload Sway configuration |
| `$mod+Shift+Q` | Close the focused window |
| `$mod+Shift+E` | Confirm logout, save session, and exit Sway |

## Automatic session restoration

Sway starts the `sway-session` helper once per login, without prompting.
It restores supported applications (foot, Kitty, LibreWolf and Bitwarden),
their workspaces, basic layout modes, fullscreen state, and floating window
sizes and positions. LibreWolf restores its own browser windows and tabs.

- Snapshots are saved every 15 seconds while supported windows exist and
  immediately before a confirmed Super+Shift+E logout.
- Session data persists across reboots and shutdowns in
  `~/.local/state/sway-session/session.json` (or under `$XDG_STATE_HOME`).
  It is local to the user and is not committed to Git.
- Run `sway-session save` to save manually. To reset the Sway snapshot,
  delete the session JSON while logged out; this does not erase browser data.

### LibreWolf preferences

The tracked overrides are deployed to both:

- `~/.config/librewolf/librewolf/librewolf.overrides.cfg` (active XDG profile root)
- `~/.librewolf/librewolf.overrides.cfg` (legacy location)

The overrides enable previous-session and crash recovery, disable permanent
private browsing, and disable automatic history clearing on shutdown.
Browsing data is retained locally as a deliberate privacy trade-off.
Restart LibreWolf after changing its overrides.

If tabs do not restore, check the profile folder in `about:support` and
verify these preferences in `about:config`:

| Preference | Value |
|------------|-------|
| `browser.startup.page` | `3` |
| `browser.sessionstore.resume_from_crash` | `true` |
| `browser.privatebrowsing.autostart` | `false` |
| `privacy.sanitize.sanitizeOnShutdown` | `false` |
| `privacy.clearOnShutdown.history` | `false` |
| `privacy.clearOnShutdown_v2.historyFormDataAndDownloads` | `false` |

### Limitations

Session restoration is best-effort, not process checkpointing. Exact nested
tiling layouts, tiled sizes, scratchpad windows, running terminal processes,
and unsupported applications are not restored. Browser windows are matched
in arrival order rather than by tab identity. A direct reboot or unexpected
shutdown can miss recent layout changes since the last snapshot. Use the
normal logout shortcut to capture the latest layout.

## Configuration updates

The update workflow is notification-driven and manual. It does not apply
updates automatically.

1. `config-update-check` starts with the Sway session, records a snapshot of
   the current Sway/session environment, waits two minutes, and then checks
   GitHub every 30 minutes using `git fetch`.
2. When the remote branch has commits that are not in the local checkout, a
   desktop notification reports that an update is available. It notifies once
   for each newly observed remote HEAD.
3. The Waybar update indicator checks local Git tracking information every
   five minutes. It appears only while updates are pending. Clicking it opens
   the interactive updater in Kitty. You can also press
   **Super+Shift+U**.
4. `config-update` fetches again, lists the pending commits, and asks before
   applying them. If confirmed, it performs a fast-forward-only pull and runs
   `sudo nixos-rebuild switch`. It temporarily switches TLP to AC mode during
   the rebuild, then restores TLP.
5. If the rebuild fails, the running system remains on its previous
   configuration. The updater offers to revert the pulled Git changes.
6. After a successful rebuild, the updater checks whether a reboot, Sway
   relog, or Sway config reload may be needed. It also signals Waybar to reload
   when files under `waybar/` changed. These checks are heuristics; reboot
   when in doubt.

Useful commands:

| Command | Purpose |
|---------|---------|
| `config-update-check` | Background update checker (normally started by Sway) |
| `config-update-status` | Print the update state used by Waybar |
| `config-update` | Fetch, review, and optionally apply pending changes |
| `sudo nixos-rebuild switch` | Manually rebuild the current checkout |

## Day-to-day changes

Edit the repository, then rebuild:

```sh
cd ~/nixos-config
# edit configuration.nix, sway/, or waybar/
sudo nixos-rebuild switch
git add -A
git commit -m "Describe the change"
git push
```

For a rollback, select an earlier generation from the GRUB menu or run
`sudo nixos-rebuild switch --rollback`.

## Fresh install notes

- Reuse the existing Windows EFI partition and mount it at `/boot/efi`;
  do not format it. Create an ext4 root partition for NixOS.
- This configuration uses GRUB with EFI support (`device = "nodev"`), not
  systemd-boot.
- Clone the repository to `~/nixos-config`, back up the generated
  `/etc/nixos` directory, and link `/etc/nixos` to the clone:

  ```sh
  sudo mv /etc/nixos /etc/nixos.bak
  sudo ln -s /home/$USER/nixos-config /etc/nixos
  ```

- Generate a new `hardware-configuration.nix` for different hardware.
- Create `/etc/wireguard/homelab.conf` separately if you want the homelab
  tunnel configured. Do not put private keys or tunnel credentials in Git.

## Known issues / notes

- GRUB's os-prober may not list Windows. If that happens, Windows can still
  be selected from the firmware boot menu; a manual GRUB chainload entry is
  another option.
- The Bitwarden browser extension is not currently configured for desktop-app
  biometric integration.

## Security

This repository is public, so everything committed here is publicly readable.
Do not commit passwords, tokens, private keys, or other secrets. The WireGuard
configuration remains in `/etc/wireguard/homelab.conf` outside the repository.

The update workflow applies whatever configuration is present in the branch
being tracked when you approve an update. Review changes before merging or
pulling them, especially changes to `configuration.nix`, scripts, and system
services.
